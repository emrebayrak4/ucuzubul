# @pricora/mobile — WhichLess app

**Rebrand (WhichLess):** app name comes from `brand.name`; slug `whichless`; schemes `whichless://` (primary) and `pricora://` (legacy, temporary); **bundle ids changed to `com.afterwish.whichless`** (iOS + Android) — a new store identity, so EAS credentials and any store listings must be created for the new id. Icons, adaptive icon, splash and in-app logo use `assets/brand/*` (copied from `packages/config/assets`).

Expo SDK 58 · Expo Router (typed routes, `src/app`) · TypeScript strict · TanStack Query (persisted) · Reanimated 4 · liquid-glass tab bar.

## Run
```sh
pnpm -C apps/mobile dev            # Metro; press a / i, or scan with a dev build
pnpm -C apps/mobile typecheck
pnpm -C apps/mobile lint
pnpm -C apps/mobile export:android # = npx expo export --platform android
pnpm -C apps/mobile export:ios
pnpm -C apps/mobile doctor         # expo-doctor
pnpm -C apps/mobile smoke:api      # live API smoke run of the app's main flows (contract-validated)
```
Use `pnpm -C`, not `pnpm --filter` (Windows long-path issue, see docs/TASKS.md).
Typed routes (`.expo/types/router.d.ts`) are generated by `expo start`; typecheck passes without them, with looser `Href` types.

## API URL
`EXPO_PUBLIC_API_URL` (origin, no `/v1`). If empty:
- Android emulator → `http://10.0.2.2:4400`
- iOS simulator → `http://localhost:4400`
- physical device in dev → `http://<Metro host LAN IP>:4400` (from Expo `hostUri`)

See `.env.example`. Release builds must set `EXPO_PUBLIC_API_URL` (https).

## Screens (parity with the shopping web, 2026-11-27)
Tabs: Home / Search / Scan / Saved / Account. Stack: product, categories (3-level tree) + category, brand, store,
browse (generic filtered listing for Home tiles/deep links), compare (≤5, "only differences"), deals, price-drops
(24h/7d/30d), popular, new, coupons, credits, account/{profile, alerts, followed-stores, notifications, privacy}.
Every listing uses `components/browse/ProductBrowser` (GET /v1/search: sort sheet, filter sheet with spec facets +
counts, price slider over the histogram, brand/store multi-select, condition/in-stock/free shipping/discount,
applied chips, grid/list, infinite pages, pull-to-refresh, skeletons). A floating compare tray (`CompareTray`)
shows on every screen while products are picked.

## Decisions
- **Tab bar (liquid glass):** iOS 26+ (`isLiquidGlassAvailable()` from expo-glass-effect) uses the system Liquid Glass
  bar via `expo-router/native-tabs` (minimizes on scroll; Scan is a regular middle tab there because the system bar
  has no custom center button). Android and iOS < 26 use `expo-router/js-tabs` with `components/GlassTabBar`: a
  floating pill inset 16 pt from the edges with expo-blur (iOS) or a translucent material (Android; real backdrop
  blur would need a BlurTargetView around every screen), an SVG specular sheen + gradient rim, a selection bubble
  that springs and squashes between tabs, a raised center Scan button and haptics. Reduce Transparency → solid
  surface; Reduce Motion → instant moves. Look and spring constants (stiffness 340, damping 26) follow
  [clayharmon/webgl-liquid-glass](https://github.com/clayharmon/webgl-liquid-glass) (MIT, © 2026 Clay Harmon);
  no code or WebGL is embedded. Tab screens pad their scroll content with `useTabBarSpace()` (`lib/tabBar.ts`).
- **App icon:** Android adaptive icon = white "w" (`assets/brand/whichless-adaptive-foreground.png`, generated from
  the mark, inside the 66% safe zone) on `#0029F8`.
- **Styling: StyleSheet + `@pricora/design-tokens`, not NativeWind.** NativeWind 4 needs Tailwind v3, and the monorepo
  hoists Tailwind 4.3 for web/admin. Two Tailwind majors in a hoisted layout is fragile, and the tokens TS object
  already covers RN (colors per scheme, type steps, spacing, radius, native shadows). See `src/lib/theme.tsx` and `src/components/ui.tsx`.
- **React 19.3.1** (same as web), not Expo's listed 19.3.0, so the hoisted monorepo has exactly one React. Excluded via
  `expo.install.exclude`; RN 0.88's renderer has no strict patch-version check. **TypeScript 5.9.3** is the repo pin (Expo suggests 6.x).
- **Charts:** hand-drawn with `react-native-svg` (no chart lib). Real points only, and the line breaks across gaps over 3 days.
- **Bottom sheet:** RN `Modal`, so no extra native dependency. The price slider uses `PanResponder` (works inside
  the Modal on Android without a nested gesture-handler root).
- **Contract checks:** `VALIDATE_RESPONSES` is on in development (every response is parsed with the Zod contract;
  set `EXPO_PUBLIC_VALIDATE_RESPONSES=0` to disable), off in release builds.
- **Real previous prices only:** cards strike through `previousPriceCents` / price-drop `previousPriceCents` (same
  store, real observation) in the drop color — never list/"was" prices. Deal rails only show it when the deal's
  offer is the lowest-price store it belongs to.
- **Photos:** promo + category photos come from `@pricora/content/*.json` (Unsplash). Promo tiles and the category
  header carry an ⓘ `PhotoCredit`; all photos are listed on the Credits screen.
- **Privacy:** "Do Not Sell or Share" sends `Sec-GPC: 1` on every API request from the device and, when signed in,
  `PUT /v1/me/consent` (advertising off, gpc on). Analytics opt-out drops events on the device. "Use my location"
  runs only on tap: one coarse fix → `GET /v1/geo/zip` (rounded coordinates); 404/no match falls back to typing.
- **Push:** Expo token registered with `POST /v1/me/devices` after login when permission was already granted (no
  prompt), on enabling push in Notifications, and removed on logout. Android channels: price-alerts, coupons.
- **Temporary `expo.install.exclude`** additions (expo, expo-file-system, expo-glass-effect, expo-image, expo-location,
  expo-notifications, expo-router, expo-sharing, expo-splash-screen): Expo shipped SDK 58 patch releases on
  2026-11-26 ~16:26 UTC, younger than the repo's pnpm minimum-release-age, so they can't be installed yet and
  expo-doctor would fail. After 2026-11-27 ~16:30 UTC: remove these entries and run `npx expo install --fix`.
- **Auth:** the `pc_session` httpOnly cookie works through the native cookie store, which acts as the fallback. Native mode: every request sends
  `x-pricora-client: native`; login/register return `sessionToken` (A04, verified live), which is stored in SecureStore and sent as `Authorization: Bearer`. Bearer requests need no CSRF; the cookie fallback still sends `x-csrf-token` from login/me. Optional biometric lock (expo-local-authentication).
- **Offline:** the TanStack Query cache is persisted to AsyncStorage (home, product, history and hotel queries only, never account data),
  `networkMode: offlineFirst`, NetInfo drives `onlineManager`, and the offline banner shows on every screen. Recently viewed is stored on the device.
- **Outbound:** "Visit store" opens `/v1/go/:offerId` (or `/v1/travel/go/...`) in the in-app browser, never a raw retailer URL.
- **Demo data:** every offer, fare or rate with `source: "demo"` shows a `DemoBadge`, and screens show a demo notice when the aggregate is demo.

## Deep links
Schemes `whichless://` (e.g. `whichless://products/<slug>`) and legacy `pricora://`. App routes mirror web paths (`/products/[slug]`, `/flights`,
`/hotels/[id]`, `/login`…), so universal links map 1:1. `associatedDomains` and Android `intentFilters` for `whichless.com` (from `brand.domain`) are
placeholders. They need `/.well-known/apple-app-site-association` and `assetlinks.json` on the web domain.
